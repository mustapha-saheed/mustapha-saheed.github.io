01 / WORK

Featured project: digitising cheque requisitions for a multi-branch firm

A professional-services firm with a head office and several branches ran payment requests on paper. I designed and built the replacement end to end on Microsoft 365.

CRF: Cheque Requisition System

Power Apps (canvas)Power AutomateSharePoint OnlineExcel OnlineExchange shared mailboxSecurity groups
Problem
Paper forms passed by hand between staff, department heads, the Head of Practice and Accounts. Requests went missing, nobody could see status, and there was no record of who approved what.
Result
One app where staff raise requests, approvers decide with comments, and Accounts track payment. Every request is numbered, permissioned and logged automatically.

What I built

Per-branch numbering

A counter list issues IDs like HO0000005 and ABJ0000001 the moment a request is saved.

Item-level security

Each request is shared only with its department or branch group and the Head of Practice. Staff never see each other's requests.

In-app approvals

Approvers act from an Approvals screen with comments. A flow checks the approver is allowed to decide at that stage before writing anything.

Configurable routing

Approvers live in a lookup list, so adding a department means adding a row and a group, not editing flows.

Accounts workspace

Accounts set Processing or Paid, record cheque numbers and deductions, and every change is written to an activity log.

Register and print

Approved requests sync to an Excel table for reconciliation, and any request prints as a clean branded form.

Engineering decisions

  • Least privilege. Users only have View on items; writes go through flows that run under a service owner's connections.
  • Server-side checks. The approval flow works out the stage and the allowed approvers itself, so the app can't be used to skip a tier.
  • Idempotent logging. A trigger condition and a LoggedToRegister flag make sure each request reaches Excel exactly once.
  • Handover ready. I wrote a runbook so IT can add a new department without a developer.
